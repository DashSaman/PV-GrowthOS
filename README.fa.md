## مقدمه

**گروث‌او‌اس** یک سیستم خودکارسازی رشد است که برای اجرا روی **سرور پرووداکشن زنده‌ی VPN** طراحی شده؛ همان سروری که مشتریان واقعی روی آن سرویس دارند. همه‌چیز در این پروژه حول یک اصل بنا شده:

> **افزایش فروش و ارزش بلندمدت مشتری PV Network با حداقل عملیات دستی.**

این سیستم در کنار سرویس‌های موجود مستقر می‌شود و **هرگز** آن‌ها را تغییر نمی‌دهد:

| سرویس محافظت‌شده | دامنه / آدرس | وضعیت |
|---|---|---|
| میرزا (سیستم فروش و پروویژن اصلی) | `robot.ahsg.top` | فقط-خواندنی |
| پنل نمایندگی PV Network | `npanel.softarg.ir` (127.0.0.1:31080) | فقط-خواندنی |
| ربات AKH | `rasteh.softarg.ir` (127.0.0.1:8307) | فقط-خواندنی |
| X-UI / Xray | پروویژن VPN | فقط-خواندنی |
| تونل‌های WireGuard / GRE / SIT و iptables/nftables | زیرساخت شبکه | ممنوعِ دست‌کاری |

## قیف رشد هدف

![قیف رشد](docs/images/funnel.png)

```
جذب کاربر → شروع ربات → کانفیگ رایگان/تست → اتصال → مشاهده تعرفه
→ پرداخت → مشتری فعال → تمدید → معرفی دوستان → افیلیت/نمایندگی → بازگشت مشتری
```

هر قابلیتی که حداقل یکی از این مراحل را تقویت نکند، پیاده‌سازی نمی‌شود — هرچقدر هم از نظر فنی جالب باشد.

## معماری

![معماری](docs/images/architecture.png)

- **مونولیت ماژولار** با نام `pv-growth-app` (نه میکروسرویس؛ سرور فقط ۲ هسته CPU و ۴ گیگابایت رم دارد)
- بایندینگ فقط روی `127.0.0.1:8350` — هرگز `0.0.0.0`
- شبکه داکر اختصاصی `pv_growth_net` (ترجیحاً `172.23.77.0/24` پس از بررسی تداخل)
- دیتابیس `pv_growth` روی سرور PostgreSQL موجود، با کاربرِ حداقل‌دسترسی و مایگریشن Alembic
- صف کار پایدار روی PostgreSQL — **بدون Redis** در نسخه اول
- حدود ۲۱ ماژول منطقی داخلی: از `events` و `attribution` تا `lifecycle`، `referrals`، `campaigns` و `experiments`

## موتور جذب کانفیگ رایگان

![خط تولید کانفیگ رایگان](docs/images/free-config-pipeline.png)

**استخر عمومی:** کانفیگ‌های عمومی از رجیستری منابعِ تأییدشده (گیت‌هاب/تلگرام) جمع می‌شوند و با فیلتر مرحله‌ای پردازش می‌شوند. نمونه واقعی: دریافت ۲۰۰۰ ← حذف تکراری ← ۵۰ نامزد ← بررسی اتصالِ محدود ← انتشار ۱ تا ۲ مورد برتر. هیچ تست سرعتِ هزاران اتصالی از روی این سرور VPN انجام نمی‌شود.

**استخر اختصاصی PV:** کانفیگ رایگان محدود با پروویژن مجاز PV؛ ادمین بدون تغییر کد می‌تواند تعداد پست روزانه، ساعات انتشار، حجم ترافیک، اعتبار، لوکیشن، پروتکل، سقف claim، محدودیت هر کاربر و اورراید تاریخ (مثلاً ۳ اکتبر ← ۵ گیگ، ۴ اکتبر ← ۱۰ گیگ) را تنظیم کند.

## موتورهای اصلی

| موتور | وظیفه |
|---|---|
| اتریبیوشن | ثبت first-touch و last-touch با پارامتر `start=`؛ first-touch هرگز بازنویسی نمی‌شود |
| رویدادها | ۲۳ نوع رویداد نرمال با کلید idempotency؛ بدون ذخیره secret در متادیتا |
| چرخه حیات | قوانین خودکار: بدون تست ← بدون اتصال ← بدون خرید ← یادآوری تمدید ← انقضا ← وین‌بک |
| معرفی (Referral) | پاداش فقط پس از خریدِ واجد شرایط و تسویه؛ ضد خود‌معرفی/کپی‌برداری/دریافت تکراری |
| پیام‌ها | قالب با متغیر (`{{price}}`، `{{traffic_gb}}` و…)؛ هوش مصنوعی فقط لحن را بازنویسی می‌کند، **نه اعداد تجاری را** |
| تحلیل | قیف، کوهورت، اتریبیوشن درآمد و نرخ تمدید — سبک و بدون پلتفرم سنگین |
| آزمایش A/B | تخصیص قطعی (deterministic)؛ تخصیص کاربر در طول آزمایش تغییر نمی‌کند |

## فازهای اجرا

![فازهای اجرا](docs/images/phases.png)

| فاز | عنوان | شرط پذیرش (خلاصه) |
|---|---|---|
| ۰ | زیرساخت و ایمنی | CI فعال، چک تداخل کار می‌کند، هیچ منبع محافظت‌شده‌ای تغییر نکرده |
| ۱ | داده، رویداد، اتریبیوشن، آداپتر میرزا | رویداد idempotent ثبت می‌شود؛ first-touch ماندگار است |
| ۲ | موتور جذب رایگان | دو پست زمان‌بندی‌شده هرگز تکراری نمی‌شوند؛ کانفیگ خراب منتشر نمی‌شود |
| ۳ | اتوماسیون فروش چرخه حیات | خریدار پیام فروشِ اشتباه نمی‌گیرد؛ cooldown و idempotency کار می‌کنند |
| ۴ | معرفی / ویروسی / همکاری | خود‌معرفی مسدود؛ پاداش تکراری ناممکن؛ پاداش فقط پس از تبدیل واقعی |
| ۵ | محتوا / بازخورد / رصد رقبا | اعداد تجاری جعل‌ناپذیرند؛ خطای رصد رقبا هرگز VPN/میرزا را تحت تاثیر قرار نمی‌دهد |
| ۶ | تحلیل / ادمین / آزمایش | ردیفی از منبع تا خرید تا تمدید قابل ردیابی است |
| ۷ | سخت‌سازی و رول‌اوت | فعال‌سازی تدریجی با فیچر‌فلگ — هرگز همه قابلیت‌ها هم‌زمان |

## مدل ایمنی (خلاصه)

- گروث‌او‌اس فقط مالک `/opt/pv-growth`، کانتینرها، دیتابیس، شبکه و لاگ‌های خودش است
- بیلد سنگین داکر روی سرور تولیدی ممنوع — بیلد در CI (گیت‌هاب اکشنز)، سرور فقط pool می‌کند
- قبل و بعد هر استقرار، تست دودیِ سرویس‌های محافظت‌شده اجرا می‌شود؛ خطا = بازگشت فوری گروث‌او‌اس
- هیچ توکن/رمز/کلید در گیت ذخیره نمی‌شود؛ ادمین احراز هویت اجباری دارد
- دستورهای `docker system prune`، `iptables -F`، `nft flush ruleset` و حذف broad مطلقاً ممنوع
- در پیام‌ها هیچ کمیابی ساختگی، آپ‌تایم جعلی یا تعداد کاربر غیرواقعی ساخته نمی‌شود
